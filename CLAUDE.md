# Veuly: notes for agents working on this code

Record a class, type notes, get one study note. A local Python server (`transcapp/`, standard
library only) plus a browser page (`web/`, no framework, no build step except the editor).
`README.md` has the user-facing description and the full file table; this file is what to know
before changing code. Keep it current: when you add a module, a setting, a file the library
writes, or a way the user interacts with the app, update the matching line here and in `README.md`.

## Rules that are easy to break

- **Three languages.** Every new `t('key')` needs the key in `en`, `es` and `ca`; a unit test fails otherwise.
- **Two kinds, one code path.** A course's `kind` (`course` or `project`, in `course.json`; missing means `course`) is set when
  it is created and never changes. Do not add `if work` wording to the screens: add a `key__work` twin of the text in all three
  languages. A new quiz question or closing section goes in `prefs.py` and in `QUIZ` / `EXTRAS` of `web/app.js`; a unit test compares them.
  A closing section's names in English, Spanish and Catalan go in `digest.NAMES` and in `index_md._NAMES` (the digest reads it back,
  the maps leave it out of the topics); `tests/test_sections.py` fails until both have them.
  The switch (`mode` in settings) only filters the side panel and picks the wording.
- **Standard library only** in `transcapp/`. The one exception, pypdf, is vendored in `transcapp/_vendor/`.
- **A course file's text is read in a child process, never in the server or under `lib.lock`** (`materials.read_file`, called by
  `add_material` on a copy in `library/.adding/`). pypdf is pure Python: a long book read in the server's own process stalls every
  request for as long as it takes, a class recording in another tab included, even with no lock held.
- **The library on disk is the user's data.** Renaming a file there needs a step in `Library.migrate`
  and a test. Deleting means moving to `.trash/`, audio excepted.
- **Veuly keeps no audio, only the transcript.** Audio exists on disk only while it is needed to make a transcript: no setting,
  trash, version, export, player or file leaves any behind. Any text at all, even with a `transcript_check`: the recording goes at
  once, both tracks, before the note is written (`Pipeline._transcribe`), and a note that fails is tried again from the transcript. No text
  at all (a failed transcription, a recording never finished): it stays so it can be tried again, and **is transcribed once more before anything is deleted**, because the 24 hours run while the app is closed or the Mac asleep: at each start (a recording left open only once 24 hours old) and when the sweep finds one past 24 hours with the app running, through `Pipeline`'s normal line, one at a time, after any class recording or waiting (`Retention._owe`, `_turns`, `_try`; `Pipeline.start(last=True)`). It makes only the transcript, with no AI call and nothing that starts Claude or Codex: the class ends `transcribed` for the person to press Write the note (`done` if it has a note). With text the audio goes as usual; with none, or if it fails, it is deleted then and `class.json` says so (`audio_expired`, cleared when a real transcript arrives) (`Pipeline._try_failed`). Try again by hand on audio already under the rule is that try too (`h_retry`); Quit stopping a try is no failure. With no whisper-cli or no model it cannot try: past its 24 hours that counts as failed once the model's download has failed, or after a further 24 hours with the app open (`audio_wait_s`, `retention.py`'s docstring). Audio an older version kept is the person's: it has no
  `audio_rule`, nothing deletes it unasked (not the sweep, not a note written again, not "The transcript is right"), and only Settings'
  one button does, after a question. **What a deletion may touch is strict:** `library.AUDIO_NAMES` directly in a class folder, by name, or inside
  what the app named in `.trash/`; what a stop left half way (`AUDIO_PARTS`, `IMPORT_LEFT`) once a day old; no other file, and no link is
  followed. **It never touches a class in use** (`Retention.in_use`: a page recording it, in the transcriber's line or being transcribed,
  `processing`, a live worker), checked with the deletion under `lib.lock` and `pipeline.lock`; `drop_audio` and `trash` refuse a class a
  page holds, `drop_audio` also one in the transcriber's line, and an import checks again under the lock after its long upload and conversion (`_still_free`, `busy_class`), replacing nothing. Deleting a class or a course calls `live.forget`, so `veuly-live/<hash>/state.json` (transcript lines) never stays in the temporary folder. A person's own original file is never touched: Import a folder gets a copy from the page, and that copy goes with the transcript. `tests/test_no_audio.py`
  has the cases, and `info_privacy_text` and `README.md` say the same in words: change them together.
- **Only a whole answer is a note.** An engine raises `EngineError` (`refused`, `cut_off`, `too_long`…) instead of returning a declined,
  cut-off or error text; then nothing is written, and the note is tried again from the transcript. On `OpenAIEngine` a `finish_reason` is an allow list (`FINISHED`, in any case): a limit is `cut_off`, `content_filter` is `refused`, anything else or none is a failure that may be retried, in a stream or a plain JSON answer. For a note only, never `complete` (Ask and others may fairly say they cannot), `_declined` on `OpenAIEngine` and `CodexEngine` takes an answer under about 600 characters with no heading that opens by declining in English, Spanish or Catalan as `refused`: a heuristic, with a short list. `OpenAIEngine` also raises `too_long` for a note when `usage.prompt_tokens` is under about a quarter of what was sent (Ollama can trim and still end with `stop`); a service that sends no usage passes. Every `claude -p` the app starts for a note or a publish
  passes `--no-session-persistence`, or Claude Code keeps a copy of the transcript in `~/.claude/projects`. The Obsidian agent is
  the exception on purpose: it edits the user's vault, and its session there is how they can look back at what it did.
- **Claude Code's Read is limited to the note's own pictures** (`Read(./img/**)`, `ClaudeCodeEngine.complete`): a bare `Read` lets text in a slide or transcript ask for any file of the computer, and with the real Claude Code it did. The Obsidian agent reads anywhere on purpose: it is off unless a course ticks it. What sits last in the request wins over the system prompt: `SHOW_PAGES_LAST` and `TRANSLATE_HEADINGS` are there because rules further up were not followed, and `prefs.in_language` names the closing headings translated (each one must be in `digest.NAMES`; `tests/test_notes.py` checks it).
- **Every engine runs without tools that can read the computer.** Text in a slide, a page saved from the web or a transcript can ask for any file, and what it asks for would reach the service. Claude Code gets no tool, or `Read(./img/**)` (above). Codex gets `engine.CODEX_SAFE`, with no flag dropped to please an older Codex: measured with the real Codex CLI 0.165.0, `codex exec --sandbox read-only` DOES read files outside its folder (it ran `cat` on a canary and printed it: read-only limits writing only); with only the first flags it also read an outside picture on request, through `view_image` inside "code mode", and the JSON showed no item for it (`-c tools.view_image=false` is ignored). The whole command, with `--disable view_image --disable image_generation --disable code_mode_host --disable multi_agent_v2 --disable sleep_tool --disable tool_suggest --disable goals`, refused the outside text file and the outside picture (one run each), obeyed the instructions file and saw a picture attached with `-i`. `engine.CODEX_ITEMS` is an allow list: `agent_message`, `reasoning` and `error` (with `code_mode_host` off every run starts with an `error` item, a warning: the turn still completes), and any other item type fails the answer, so a tool a later Codex adds cannot pass as text. `collaboration.spawn_agent` is still offered to the model: not used in those runs, and a helper should inherit the flags, but that is unproven, so `collab_tool_call` stays a failure. `CODEX_TESTED` is the version measured; Setup's Codex line says when the installed one differs (`codex_unchecked`), without blocking. `OpenAIEngine` offers no tools at all. Those measurements were by hand; in the code, `CodexEngine` and `OpenAIEngine` have run on stand-ins only (`tests/test_providers.py`), never against a real service.
- **A key goes only to its account's own address.** `OpenAIEngine` never reads a key from the environment; it and `ApiEngine` follow no redirect (`_NoRedirect`: neither the key nor the text goes on); only `https`, or `http` to 127.0.0.1 / localhost (`clean_base_url`, also through `check_settings`); a new address deletes the key given for the old one (`accounts.set_service`, `h_settings`), and Setup's is stored under a name made from its address (`setup_secret`), so a settings.json edited by hand cannot send it elsewhere.
- **The app never handles a Claude.ai or ChatGPT login.** Signing in happens in the vendor's own tool in a Terminal; the folders of `claude-accounts/` and `codex-accounts/` are made empty and never read. API keys stay the recommended route on the page, Claude Code and Codex stay under Advanced, Setup never requires either, and nothing says "use your subscription" or suggests a vendor endorses Veuly: plain-text names only.
- **Addresses never leave the computer through the app** (`transcapp/recipients.py`; `mail_to` in `class.json` and a project's `course.json`; `Event.mails`, not in the home page's answer). The E-mail button (`web/share.js`) puts them in a `mailto:` link the person sends from their own program. Nothing reads `mail_to` for a request, a map, a vault or Confluence: `tests/test_recipients.py` checks the note request and the maps.
- **Every AI call goes through the course's account** (`transcapp/accounts.py`). An engine is made only from
  `accounts.settings_for(settings, course=… | side=… | account=…)` (never from the bare settings: `tests/test_accounts.py` scans
  for it), and every `claude` the app starts gets `accounts.child_env` (with the account's folder for a login): a new call that
  starts Claude takes its course's account the same way, or a work project's minutes go through the personal account. An id no
  longer listed falls back to the side's choice, then to this Mac's Claude Code, never to an error at Finish. "This Mac's Claude
Code" runs with no `CLAUDE_CONFIG_DIR`, and this Mac's Codex with no `CODEX_HOME`, as before accounts existed. The app makes an account's folder empty and never reads,
  copies or writes what Claude Code or Codex keeps there; `settings.json` lists accounts by id, name, kind, address and their own models if they chose them, a key is
  in `keystore` only. Tests never run a real `claude auth login` or `logout`: a stand-in `claude` notes `CLAUDE_CONFIG_DIR`.
- **Moving into `.trash/` is one `os.rename` (`_trash_path` names it), never `shutil.move`**: on Windows a move copies, then
  deletes file by file, and stops half way at a file another program holds. What replaces a transcript (Import) keeps the old
  one in `versions/`, and the answer's `kept` says where; a recording it replaces is deleted, not moved. `Library.trash` takes a
  class's audio out first, so the trash gets none. Only `tidy_trash` and Settings' old-recordings button delete from `.trash/`, and only what
  the app named there: `tidy_trash` by the limits it had when an older version put recordings there (they are also counted as old audio).
- **The app's JSON files are read with `Library._load` / `paths.load_json` and saved with `write_atomic(..., keep=True)`**,
  never with a bare `json.loads`: one damaged file must never stop the app or hide the others. Everything a folder outside
  the library holds (the Claude-project inbox, a vault) is checked the same way: `/api/state` must answer whatever is there.
- **Every refusal has a kind.** An `HttpError` or `library.Refused` carries one, with an `h_<kind>` text in three languages
  listed in `HELP_KINDS`; the `error` message is only the English detail. `tests/test_storage.py` checks the list.
- **A program that can run for minutes (whisper-cli, ffmpeg or the Mac's `afconvert`, Claude Code) starts through `paths.run_child`**
  (or `paths.start_child` / `end_child` when its output is read as it runs, as `run_whisper` reads whisper-cli's progress), not
  `subprocess.run` or a bare `Popen`, so that Quit stops it and what it started; quick checks (`security`, `sips`, `claude --version`,
  `whisper-cli --help`) need not, nor `caffeinate`, which `-w` ends with the app.
- **A title the user typed is theirs.** `title_auto` in `class.json` says the title is still the app's: the date a new class
  gets, then the note's own first line. Typing one on the class page sets it to false, and nothing replaces it after that: code
  that names a class goes through `Library.take_title` (under `lib.lock`, so a title typed meanwhile wins), never a bare
  `update_meta(title=…)`. A class made before `title_auto` existed counts as the app's only while its title still reads like its
  date (`titles.default_title`: the words of `class_of` and a date with a day and a year, nothing else; "Clase del tema 4" and
  "Class of 12 Oct 2026: guest lecture" were typed). The note's first line
  is its title because `SYSTEM` / `SYSTEM_WORK` ask for it: a change to the prompts keeps that line, or new classes keep their date.
- **Once the note is written the class is done**: a step after it (Confluence, the vault) reports its own failure and never turns the class into an error (`_step_failed`, `_after_done` in `pipeline.py`).
- **Anything that changes a course, its files, its preferences or a class must end in
  `lib.refresh_maps(slug)`**, or the developer maps and the notes waiting for a linked Claude project go stale.
- **A school course's study files are the student's data**: `review.json` (the learning record; read with `paths.load_json`,
  written with `write_atomic(keep=True)` under `lib.lock`) and `practice/` (the practice exams) live in the course folder, so they go
  to `.trash/` with it; the class list ignores `practice/` because it holds no `class.json`. A practice exam goes to the trash by one
  `os.rename`. Grading a card changes nothing on any map, so it does not call `refresh_maps`; writing or deleting an exam does.
  A practice exam is a whole answer of `engine.complete` or nothing (`EngineError`).
- **Nothing internal goes into the notes folders.** A student sees their notes, transcript, images
  and files there; developer aids go to `dev-maps/` and only in developer mode.
- **The app is called Veuly; the code folder is still `transcapp/`** and the old environment variables still work. Do not rename the package without a plan for the installers.
- **A class folder may hold `audio2.pcm` / `audio2.wav` while it has a recording**, the computer's sound as its own track. Anything that deletes, converts or replaces the recording must handle both.
- **The app never reads or writes a Claude project itself**: it cannot. A Claude task fills `claude-projects/<slug>/` and, when the link says `send`,
  puts the files of `out/` into the project under `veuly/<slug>/`. Sending is per link and off unless the user ticked it. Only the final note is
  copied to `out/`, never the transcript, the typed notes or images. A document's path and hash must depend only on its own class (not on the
  course's name or on sibling classes), or every sync rewrites documents that did not change. A sent note must never return as project context:
  it starts with `claude_link.MARK` and `_doc_files` drops it. The Claude task is also driven by the user's `transcapp-sync` skill, which defers
  to `README` but must not contradict it.
  What arrives there is outside data: only `card.md` and plain `.md` / `.txt` files directly in `docs/` are read, sizes are capped,
  and a pack whose `synced.json` names another project is shown but not used. Changing what the task must write means changing
  `claude_link.README` and `FORMAT` together. The inbox is next to `library/`, never inside a notes folder.
- **An error answer to an upload must come after the body was read** (`Handler.drain`, called by `Handler.json` for every error answer): closing with unread data resets the connection and the page shows "Failed to fetch" instead of the reason. A handler that reads `rfile` itself sets `self.unread = 0`, and a body shorter than its `Content-Length` is refused (`connection_cut`), never stored.
- **The server trusts nothing from the page**: names go through `NAME` / `safe_name`, and every
  route needs the cookie and the session token itself in the `X-TA` header (see `Handler.dispatch`): the browser hands
  the cookies of 127.0.0.1 to every program listening there, so the cookie alone only reaches `/files/` (a class's pictures,
  the course's PDFs: an `<img>` or frame sends no header). The page
  takes the token from the launcher's `?t=` link and keeps it in `sessionStorage`, so a tab opened without that link
  cannot use the app. A `fetch` that bypasses `api()` must send `X-TA: sessionToken` too (only `/api/ping`, which `api()` asks
  to tell a stopped app from a cut connection, is answered before the cookie and the token are checked). Settings that name a program,
  the model file it gets, a model or where the API key goes pass `Handler.check_settings`.
- **The pages load nothing from outside** (`CSP` in `server.py`, sent with every HTML page): no inline scripts, no `eval`,
  no outside image, font or script. A picture on another site in a note is a link that names the site (`outsideImage` in
  `web/md.js`; the editor leaves its line as text). In a browser test, `page.wait_for_function` needs an arrow function
  (`"() => ..."`): a bare expression is run with `eval` while it waits, which the policy refuses.
- **Outside text cannot leave its block.** `engine.build_prompt` makes the request's own tags inert in every text it wraps
  (`_inert`) and cleans every name put in a tag's attribute (`_name`): a document saying `</linked_project_document>`
  cannot pose as the user's `<requested_changes>`. A new tag of the request needs an underscore in its name, or a place in `_TAG`
  (as the `<class …/>` / `<meeting …/>` line of `_about` has, in the shapes of a tag only, so `template <class T>` stays as it is).
- **`go` is the only way to change page, and only its newest call may draw.** It waits for the server; a call that answers after a newer one
  started must stop (`stale()`), or it redraws over what the user is doing. New awaits in `go` need the same check after them. It loads
  everything the next page needs before it changes `S.view` or `S.cls` (a failure leaves the page on screen working), saves what was typed
  meanwhile, and does not leave notes or final-note edits that are not saved unless the user discards them. A page is `VIEWS[name]` in
  `web/app.js`, and what it needs from the server first is `LOADERS[name]` (its answer is `S.data` while that page shows). A page of its own
  lives in a file loaded after `app.js` (`search.js`, `digest.js`, `source.js` in `index.html`) that adds itself to both; `start` waits
  for every script, so it may. The class page takes `go({ name: 'class', slug, cid, tab, at, section })`: `tab` opens that tab, `at`
  (seconds into the recording: `showMoment`, which `source.js` fills in) and `section` (a heading of the final note as written there:
  `showSection` takes the one with exactly that text, or else the first that starts with it) say what to show once it is drawn;
  `from` (a heading of the note) gives the Transcript tab its "Back to" there. The time of a typed line in My notes goes
  there with `go({ …, at })`. `SIDE_TOP` adds to the top of the side panel,
  `NOTE_TOOLS` buttons to the Final note tab (`share.js`), `CLASS_NOTICES` a notice above the class page's status bar (redrawn with it: `tasks.js`, `voices.js`),
  `COURSE_ACTIONS` buttons beside a course's New class (`folder.js`), `SETTINGS_PARTS` a section to Settings after Notes (`calendar.js`, `accounts.js`),
  `COURSE_SETTINGS_PARTS` a sheet to a course's settings page before its details, `COURSE_FILE_PARTS` a part to the files sheet and `MATERIAL_MARKS` a mark beside a course file (`foldersync.js`), `ERROR_ACTIONS` a button after Try again on a class that failed (`accounts.js`),
  `HOME_TILES` a tile to the home page (a function of the `/api/home` answer returning an element, or null so that only tiles with something show; its data

A picture's name is checked against what is already in `img/`, so one of the user's is never written over; only a picture listed in `page_pictures` is reused or replaced, and none is deleted (`versions/` may point at it).

- **A question is not a note.** `POST /api/ask` writes nothing to the
  library or a notes folder, and reads only the courses of its scope: a course outside it must never reach the request
  (`tests/test_ask.py` checks it). Everything taken from the library goes into the request through `engine._inert` / `_name`, as the
  note request's outside text does; the question is last, in `<user_question>`. Only a whole answer counts (`EngineError` as for a note).
- **Catch me up is not a note either, and it happens only when pressed.** Nothing starts it by itself; nothing it answers is stored (not in `class.json`, not in a file, in `App.asks` only until `KEEP_S`); it goes through the course's account (`tests/test_accounts.py` scans `h_catchup`). What was muted never goes, an open mute too (`Live.so_far`). Only "Put it in my notes" writes its text, as the app's own change at the end of My notes (no user event: no typed time, the cursor stays), without stars or `??`, which mean something in My notes; only then does it reach the final note. The answer box is outside the status bar, and a late answer draws only if it is the newest press (`entry`).
- **A heads-up is the one Claude call that happens without a press, so nothing may start it for a project that did not choose it.** Only `headsup: true` in a project's `course.json` starts it (`headsup.chosen`, checked at each chunk with no thread yet and again at each check); `Library.update_course` never sets it on a school course, and a school course's page draws and asks nothing. A new way to start it, or a default that turns it on, breaks this rule. It runs only while the class records, with at least `NEW_S` of new unmuted speech (`Live.so_far`: what was muted never goes), never beside another call of the class, never while a class waits for the transcriber, and any error stays in `transcapp/headsup.py`: `ensure` runs after the chunk was answered (`live_worker`), no lock is held while Claude answers, and `end` waits for nothing, so the recording, the live transcript and Finish behave as with it off. A `claude` or `codex` still running at Finish, at the switch or past `CALL_LIMIT_S` is stopped at once through the process groups Quit uses (`paths.Watch`, `watching`, `stop_watched`); a request already sent to the API cannot be, and its answer is dropped. What was said with the switch off never goes, as with a mute (`Session.quiet`). Always a small model (`engine_settings`: Haiku on Anthropic's ways, never the account's model there) through the project's own account. Nothing it says is stored: `Session` is memory only, gone at Finish or a restart; only Put it in my notes writes its text (`notesAppend`, the app's own change). Nothing outside this project reaches the request, and a message without a known `[S#]` shows nothing (`parse`). A card lies over the list inside the pane (`.hu-cards`) and must neither cover My notes nor move anything: not the editor, its cursor, the list or the status bar. In a window 1000 px wide or less, where the pane is above the notes, the list has a place of a fixed height from the start on a project that chose it (`.hu-top:not([hidden]) ~ .hu-over`) and a card stays inside that place; never `position: fixed` over the notes. Through the API a check's own engine is capped and tries once (`_short`: `MAX_TOKENS`, `waits`), which leaves what a note sends alone; it takes no focus, makes no sound, and never reaches a Mac notification or the menu bar (a shared screen could show it). A source shows its quote in place, never `go()`.
- **Search reads the library and writes nothing of its own** (a damaged `course.json` or `class.json` it meets is set right by
  `Library._load` / `_summaries`, as `/api/state` would). It never takes `lib.lock`, never reads `.trash/` or a dot folder, and searches a course
  file in the text kept when it was added (`materials/.text/`), never extracting it again. A new text file of a class (or one renamed)
  needs its place in `Search._refresh` (`transcapp/search.py`), or it is not searched.
- **Every calendar link is a secret.** Each is kept only through `keystore`, under its own name (`calendar_ics.secret_of(id)`:
  `calendar-url-<id>`), never in `settings.json`, the list (`calendars.json`: id, name, side, the site's host and the moved note), a
  log, an error message or an answer: the page gets `where` (the site's name) and nothing more; urllib's own messages quote the
  address, so `clean_url` and `fetch` pass on only the kind of failure. Removing one deletes its secret first, then the entry.
- **The list of calendars stays out of `settings.json`**: a version that does not know a setting drops it when it saves its settings
  (0.6.0's school / work switch does), and every calendar would be gone. The single `calendar-url` of before is moved by
  `Calendars._migrate`: set the new secret, read it back, `keystore.sync_secret`, save the list, and only then delete the old one, so a
  stop at any step loses nothing and the next start finishes it; `FIRST`'s secret with no entry goes back on the list; a full list
  leaves the old link waiting. Never fetch a link in a test: tests serve calendars on this computer (only `http` to 127.0.0.1 or localhost
  is taken besides `https`; another `http` link is asked over `https`, and `_Redirects` follows a redirect only over `https`, never
  to this computer unless it came from it); a test that needs an Outlook address replaces `calendar_ics.fetch`.
- **A calendar belongs to one side** (one holding both classes and meetings is linked twice, once per side; the move does that
  by itself, `both`, because the one link of before served both). A side's home page shows only the events of that side's calendars (`home_part`), the
  Microsoft no-attendee rule is the rule of the calendar each event came from (`now_next`), and Start finds the event only in a
  calendar of the course's side (`find(…, side)`). Each calendar is fetched on its own and in parallel (`Calendars.read`); one that
  fails never hides the others' events (`troubles`). Keep `/api/home` quick: a copy is parsed once, and an old one is shown while it
  is fetched again (`STALE_WAIT_S`).
- **The transcriber's line is taken in `Pipeline.start`**, before its thread starts, so classes started one after the other are
  transcribed in that order (Import a folder relies on it); `_run` leaves the line in its `finally` (`_leave_line`) whatever
  happened before its turn. A class there says `step: "waiting"` at once. A class not brought in by an import goes before the
  imported ones still waiting (`_join_line`, `Pipeline.imported`), never before the one being transcribed: a meeting recorded
  during a long import is not held for hours. A class imported with "Only transcribe" keeps `only_transcribe` in `class.json`, and
  `h_retry` transcribes it without writing (after an interruption, or Transcribe again) until "Write the note" clears it.
- **A synced folder is the person's: read only.** `foldersync.py` writes, moves and deletes nothing there and sends nothing anywhere; the one rename it does is a course's own copy into `.trash/`. It reads only a folder the person linked, first when they chose it (`Sync.add`), never Desktop, Documents or Downloads unasked; it never follows a symlink out of it, and never opens a pipe. `/api/state` must answer whatever `synced` holds (`clean`). A folder that cannot be read changes nothing (`trouble`, once); a version that is empty, unfinished, unreadable or without text never replaces a good copy and leaves its record as it was (`held`); what was left out is named (`left`, `blind`, `more`), never a short list as if it were all; a too-wide folder is refused by `_too_wide` when linked and at every look (a path edited by hand), and a test checks real folders with `_too_wide` itself, never with `add`, a route or a look (those get temporary folders only: the data folder is a too-wide one); a file gone from one stays in the course (`gone`), so nothing there can ever empty a course; a hand-added file with its name is left alone (`Clash`). A file's record is written in the same write of `course.json` as the file's entry, so a stop half way adds nothing half. Nothing here runs under `lib.lock` but a short edit of `course.json`. While a class records a look does nothing, not even a listing, and one under way stops at the listing's next check or before its next file (`held_back`; the file being read then finishes, its reader at a low priority); with no linked folder there is no thread (`start`). The look before a note is waited for `FINISH_WAIT_S` at most and its failure is never the note's; a look after that may replace a course's PDF while Claude writes, and then the note is written without that file's pages (`pages.stamps`), never with a page Claude did not read.
- **Import a folder never reads a folder itself**: the page's chooser hands it the files (a server listing Desktop, Documents or
  Downloads makes macOS ask). `plan` calls a file "already" only if its class has a transcript or audio (`Handler.imported`): an import interrupted past its one more try can be brought in again. A file that fails to come in leaves no class (`h_course_import` puts the half-made one in the trash).
  A recording is refused (`disk_full`, and the page stops sending) when it would leave less than `FOLDER_ROOM` free for recording.
  A file's name is taken in NFC (the page, `plan`, `h_course_import`): the Mac app's WebKit hands names over decomposed as macOS keeps them.
  `transcribed` is a status of its own: a new place that lists statuses (badges, filters, what a status allows) handles it.
- **A keyboard shortcut is a Control combination, or ⌘K.** The Mac app's menus own ⌘ and its standard keys, and Option (Windows' AltGr,
  sent as Ctrl+Alt) types @ # | on Spanish and Catalan keyboards: a key with Alt is never taken. A key acts only where it can do
  something (otherwise the browser and the editor keep it), never while an input method composes, and on a Mac Ctrl+K in a text stays
  the system's "delete to the end of the line". Info lists every key (`INFO_PARTS` in `web/search.js`). The one exception is the
  Review page (`web/study.js`): Space shows the answer and 1-4 grade it, on that page only, never in a field, with a modifier, while
  an input method composes or under an open pop-up; its own `INFO_PARTS` entry lists them.
- **Watched folders are the user's own (Desktop, Downloads).** `incoming.py` only lists them and reads new image files: it never moves, renames
  or deletes there, never looks inside before a recording starts (that is what makes a Mac ask for permission), and judges "new" by what was
  there when the recording started, not by dates. An image put into the notes automatically must not move the cursor off the line being typed.
- **Animation rules**: only `transform` and `opacity` (and colours) move; under 300 ms; nothing animates on a redraw of the page the user is on
  or on anything typed, nor in a hidden page (WebKit runs no frames there, so a fade-in would leave it blank: `arrive` skips it); every new
  motion gets its `prefers-reduced-motion` line in `app.css`.
- **The class page redraws only its status bar** (`refreshStatus`) while a class is open, so the
  editor keeps its cursor and undo. Do not call `renderMain` from recording code. The live transcript's pane (`web/live.js`) updates
  itself: it adds rows to its own list and touches the editor only when a line is clicked.
- **The transcript while recording never stands in the recording's way, nor in Finish's.** Its worker is started after a chunk is
  on disk and answered (`live_worker` swallows any error), reads the raw tracks only for a moment under `lib.lock` (Finish deletes
  them under it; Windows cannot delete an open file), writes only the transcript file and `live_upto`, and only while the class still
  records. A worker that gave up (`FAILS` failed slices, no whisper-cli) is not started again by the next chunks (`GAVE_UP`).
  There is one whisper-cli at a time (`Pipeline.whisper`): a slice runs only when no class waits for the transcriber, at a lower
  priority and with a short time limit, so a transcription waits for one slice at most. A cut with no real pause on a track may split a word (`hard_cut`, `hard` of each slice, per track): the pane shows what was decoded, and Finish decodes that track again across the cut, so a change to the cuts is measured on speech with no pause (`transcapp/live.py`'s docstring), not only on `say` with its punctuation. A slice Catch me up asked for (`fresh`) is kept like any other, its cut usually hard, and it needs `FRESH_MIN` seconds of sound. Whisper's `--prompt` does nothing with the `-mc 0` every run here passes. `Live.finish` is used only from Finish, and any
  error in it means the whole recording is transcribed as before (`Pipeline._transcribe`); a kept slice counts only with the same sound
  (its checksum) and the language the whole recording is found in. While `live_upto` is set, `2-transcript.txt` is only the part
  transcribed so far: nothing writes a note from it (`h_retry`), nothing keeps it in `versions/`, and whatever writes a real transcript
  sets `live_upto` to None (the pipeline, a transcript imported). What every transcription ends with (cleaning each track against its
  sound, `_recover`) is `transcribe.finish_tracks`, for both paths: change it there. Browser tests run it only with a whisper-cli they
  name in the settings (`tests/guards.py`), never the computer's own.
- **One tab records a class, and a chunk is never skipped.** Chunks, mutes and the finish carry the session `/record` gave the tab;
  the server refuses another tab while that one is heard from (`recording_elsewhere`) and anything once the class stopped recording
  (`recording_closed`). The page stops at such a refusal and says plainly how much never reached the server (`rec.lost.seconds`, `rec_part_lost`): there
  is no rescue as a file, since Veuly keeps no audio. A chunk is answered only once it is on disk; `audio_bytes` / `audio2_bytes` in `class.json` say how much of each raw track is good.
  Mutes go through the chunk queue, so nothing awaits the server, and every wait for the server has a deadline.
- **The page saves typed text with the revision it started from** (`live_base`, `note_base`). Without it an old tab overwrites newer notes;
  with it a conflict keeps both versions (`versions/my-notes.<time>.md`, `final-note.<time>.md`) and the user chooses.
- **A typed line's time is keyed by its text** (`typed` in `class.json`): FNV-1a of the line's NFC UTF-8 without the spaces and
  tabs around it, made by `typed.key` in Python and `lineKey` in `web-src/editor.js`. Change both together (`e2e_write.py` compares
  them), or every saved time stops matching its line. A time is saved only with the notes it is about (`typed` next to `live` in
  one request), so a refused save drops both; the page sends the times keyed again at every save, so an edited line keeps its time.
  Where the page keeps its own `S.cls.live` over the server's (`saveLive`, `poll`, `afterAction`), it keeps `S.cls.typed` too.
  Only this tab's recording gives a new line a time (`clock` is `null` otherwise); every other edit keeps, moves or drops times.
- **The clipboard write starts in the click itself** (`copyParts` in `web/share.js`): Safari and the Mac app's WKWebView refuse
  `navigator.clipboard.write` after an `await`, so everything copied is made before it is called, and anything that must wait
  for it (E-mail opening the mail program) comes after it. A link to another program (`mailto:`, `obsidian:`) does not leave the
  page, but Chrome asks the page's `beforeunload` before following it: `toOtherProgram` in `web/app.js` keeps that from asking
  "Leave site?" while something records or is unsaved. A new kind of such link goes there (and in the Mac app's `outsideSchemes`,
  `packaging/mac/Browser.swift`, which opens these links with the system).
- **The Obsidian vault is the user's own folder.** Write only inside the folder the course chose (`clean_folder` keeps it under the vault), never read it back, never delete in it, and never overwrite a file the app did not write.
  The Obsidian agent is the one thing that reads and edits the vault, and it is not the app's code: it is Claude Code started in a folder of the vault, under the
  CLAUDE.md the user wrote there. It is off unless the course ticked it, it is refused where no CLAUDE.md exists (`agent_home`), its permission mode is only
  `acceptEdits` or `auto` (never one that skips every check), and its prompt says which note arrived, not how to file it: filing rules belong to the user's
  CLAUDE.md. It starts after the class is `done`, so a slow or failed agent never holds back or loses a note; the class page follows it without reloading the class.
- **`/print/<ticket>` is the one place that shows a note without the cookie**, because the browser that makes the PDF is a separate one. A ticket is random,
  lives two minutes, is dropped when the PDF is made, and opens one class's note and images only. Do not widen it, and never put the app's own token on a command line.
- **What a page prints with `window.print()` is in the page before the call and stays there while the page shows** (the digest's formula sheet is
  `.dg-print`, shown only by `@media print`). In the Mac app the web view prints nothing by itself: `window.print` posts to the app, which prints
  the page later, so anything added just before the call and removed after it would not be on paper. The same goes for `document.title`, which
  names the PDF: the digest sets it before the call and puts it back on `afterprint` or a few seconds later (`nameSheet` in `web/digest.js`).
- **A program the app starts is found by `paths.find_program`** (Claude Code by `platform_setup.find_claude`) and started by the
  path it returns, never through `shutil.which` alone: opened from Finder, PATH is `/usr/bin:/bin:/usr/sbin:/sbin`, and Setup
  would show ✓ for a program the rest of the app then cannot start. The Mac's own tools in `/usr/bin` (`sips`, `afconvert`,
  `open`) are on that PATH and need no search.
- **Secrets (API key, an account's API key, Confluence token) go through `keystore`**, never into `settings.json`, logs or API answers. Nor does the
  session's token: the link that carries it is printed to the console only, and `veuly.log` gets the address without it.
- **Never start a real recording or spend Claude usage in a unit test**: use the stand-in
  transcriber and `FakeEngine` from `tests/test_core.py`.
- **Every line of a transcript is checked against the recording's sound** (`clean_track`): a test whose stand-in whisper writes lines over
  a silent recording gets them dropped, so give the recording sound where the lines are. A stand-in that must show progress or a language
  prints what whisper-cli prints (`make_whisper` in `tests/test_transcription.py` does): one `-of` per `-f`, `-dl` to only find the language.
- **The Mac app is a window around the same page and server, never a second interface.** What the page does, it does in
  the app too; the app adds only what a web view lacks (menus, panels, this Mac's sound, keeping the Mac awake). Its texts
  are `mac_*` keys of `web/i18n.js` in all three languages (`tests/test_macapp.py` checks every key the Swift code and
  `web/native.js` use). `web/native.js` must do nothing without `window.veulyShell`. The page keeps owning a recording:
  this Mac's sound arrives numbered by the sample (`at`), and the page decides what is silence, what is late and how the
  two tracks line up; a stalled, stopped or restarted Mac sound must never hold back the microphone's track (a new source
  takes the old one's track; the old one is filled with silence until then), and when a recording ends its last chunk
  holds all of the microphone. Code on Core Audio's
  real-time thread (`TapReader`, `SoundRing.write`) never allocates or waits: it copies, and only ever tries the lock.
  The app's main-thread work goes through `Main.run` / `Main.after` (the run loop), not `DispatchQueue.main`: AppKit's
  "quit?" wait and modal alerts block the main queue's other blocks, and the app would wait for them forever.
- **The Mac app's test mode never meets a permission prompt or the user's things**: the stand-in sound instead of the tap,
  never the microphone (a test that needs one replaces the page's `getUserMedia` with a tone of its own), test-mode panels
  and menus instead of real ones, links written down instead of opened, the window off screen and no Dock icon; it refuses
  to start without a `VEULY_HOME` of its own. `e2e_macapp.py` builds a copy with the identifier `app.veuly.test`, so the
  real app's settings and WebKit data are left alone. WebKit sees that off-screen window as hidden: every recording there
  is one with the window hidden.
- **A server that stops by itself costs what the page holds only if the new one will not take it, and then the page says so**: the page stops recording at once and keeps what the
  server never got, queued under the recording's session (`rec.session`, which `class.json` keeps), and after Start again
  the same page (not a reload) takes the new cookie and token, sends it under that session and lets the class go
  (`serverGone`, `resume` in `web/native.js`). What the new server refuses, or does not take within 20 s, is lost, said by the
  page's own `recordingLost`; `quitState` asks before quitting with a queue not sent (`unsent`).
  A Finish the dead server never answered is done then (`letGo`, `finishNow`); meanwhile the page starts no new recording
  (`rec.handing`), and `finishClass` / `completeFinish` check after every await that `rec.recorder` is still the recorder
  they began with (the old Finish may wake up only after the next class started recording: a hidden page's timers are slow). A new server on another port is another
  origin: the old page `handOver`s its queue and unsaved notes to the app, which gives them to the new page
  (`takeOver`; it shows the class that was on screen again only if the person has done nothing on the new page: `S.acted`, set by
  any `go` of theirs and at the very top of `startRecording`, before the microphone answers. That navigation is `go(view, true)`, the
  page's own, as is its first page at start: it does not set `S.acted` and gives way to it even while it loads. Never test `rec.recorder`
  or `S.view` for this: both change only after an await). The server tells the app every process group it starts (`paths.on_child`, set by `app.py` with
  `--quit-with-stdin`: "Child: <pid> started|ended" on its console); when it dies the app ends those still running
  (`Server.endChildren`), so a crash never leaves whisper-cli or Claude Code running.
- **Nothing the app shows outside its window appears in test mode**: no menu bar item (only its menu, which the test
  reads and presses: `/statusmenu`), no notification and no permission question (written down: `/notification` clicks
  one), a stand-in login item; `/sleep` plays the system's sleep and wake notices. A
  build of the Mac app (`build_mac.py`) replaces a `Veuly.app` only when the script made it and it is not running.
- **Tests never touch the user's Keychain.** On a Mac `keystore` uses the login Keychain whatever the data folder is, so every test file sets
  `VEULY_SECRETS=file` next to `TRANSCAPP_HOME` (secrets then live in files of the temporary data folder); a new test file must do the same.
  `test_secrets_stay_out_of_the_system_store` fails if keystore starts a program under it. Every browser test also does `import guards`
  after its `transcapp` imports (`tests/guards.py`): the picture watcher's default folders are empty (no real Desktop or Downloads) and
  Claude Code is a stand-in (its `auth status` reads the Keychain), so the test is safe as a plain command; a new browser test does the same. `e2e_macapp.py` imports no
  `transcapp`: its server runs inside the app it builds, with a temporary `HOME`, no note engine and the picture watcher off.
- Tested on Linux and, in parts, on a Mac (Apple silicon), the Mac app included (in its test mode: the real microphone and
  the real Core Audio tap were never run, they need the owner's permission); not yet on Windows. The README's last section
  lists what is and is not verified.
